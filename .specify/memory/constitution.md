# DBML Editor 章程

## 核心原则

### I. 隐私优先

所有数据处理必须在客户端进行。用户数据、数据库 schema 或编辑内容不得传输到外部服务器。适用于：

- DBML 源码编辑
- ER 图渲染
- 导入/导出操作
- 临时解析结果

理由：用户信任将敏感的数据库 schema 托付给此工具，服务器传输会破坏信任和隐私保证。

### II. 实时可视化

DBML 源码的变更必须立即反映在 ER 图中，无需手动刷新。编辑器与图的同步必须：

- 用户输入后 500ms 内完成同步（100 表以内的 schema）
- 优雅处理解析错误，不阻塞可视化
- 仅非视觉属性变更时保留图表布局

理由：实时反馈是该工具区别于静态文档生成器的核心价值主张。

### III. 类型安全

所有 TypeScript 代码必须保持严格类型检查，禁止使用 `any` 或 `@ts-ignore`，例外情况：

- 外部库类型定义（monaco-editor、@dbml/core、AntV X6）
- 有 JSDoc 兜底的显性边缘情况

所有新代码必须使用 TypeScript 并启用 strict 模式。

理由：复杂的图表操作和 DBML 解析需要可靠类型契约来防止运行时错误。

### IV. 测试纪律

所有新的工具函数和业务逻辑必须在 `tests/unit/` 中有对应的单元测试。端到端测试必须覆盖：

- DBML 解析和渲染流程
- 每种支持数据库格式的导入/导出
- 核心编辑器交互

代码覆盖率目标：

- 单元测试：src/models/、src/services/ >80%
- 端到端测试：关键用户路径（至少 3 个场景）

理由：导入/导出精度直接影响用户对生成 SQL 的信任。

### V. 浏览器优先架构

所有功能必须在无服务端渲染降级的情况下工作。可以渐进增强，但：

- 核心功能必须仅启用 JavaScript 即可工作
- 在技术可行时应保持离线能力

理由：该项目是客户端 Web 应用；服务端依赖会增加部署复杂性和隐私顾虑。

## 附加约束

### 技术栈

- **框架**: Umi 4（Ant Design 生态系统）
- **编辑器**: Monaco Editor（VS Code 核心）
- **图表引擎**: AntV X6
- **DBML 解析器**: @dbml/core
- **语言**: TypeScript 5.x
- **测试**: Jest（单元）+ Playwright（E2E）
- **包管理器**: pnpm

### 兼容性要求

导入/导出必须支持：

- MySQL DDL
- PostgreSQL DDL
- MSSQL DDL
- Oracle DDL（基本结构）
- JSON schema 格式

导出必须在目标方言能力范围内保持与源码 DBML 的语义等价。

## 开发工作流

### 代码审查要求

- 所有 PR 在审查前必须通过 `pnpm test` 和 `pnpm format`
- 影响图表渲染的 PR 必须包含视觉回归检查
- 导入/导出的破坏性变更必须更新兼容性矩阵

### 质量门禁

- TypeScript strict 模式：不允许警告
- Linting：不允许错误（prettier + eslint）
- 单元测试：全部通过
- 端到端测试：关键路径通过

### 提交规范

遵循 Conventional Commits 格式：

- `feat:` 新功能
- `fix:` 缺陷修复
- `refactor:` 重构（无行为变更）
- `test:` 测试添加或修正
- `docs:` 文档更新

## 治理

本章程优先于所有其他开发实践。修订需要：

1. 记录变更提案
2. 说明变更需求的理由
3. 影响评估
